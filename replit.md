# Podpedia

An automated podcast processing pipeline that ingests RSS feeds, downloads audio, transcribes content, and extracts structured data (guests, companies, themes) using local LLMs.

## Architecture

- **Language:** Go 1.26.1
- **CLI Framework:** cobra (spf13/cobra)
- **Build System:** Makefile + Go modules + go.work workspace
- **Plugin System:** WebAssembly (WASM, wasip1) via tetratelabs/wazero

## Project Structure

```
├── main.go              # Entry point
├── cmd/                 # CLI commands (root, run)
├── internal/            # Core pipeline logic
│   ├── kernel/          # wazero host kernel + capability bindings + adapters
│   ├── pipeline/        # Pipeline orchestration
│   ├── protocol/        # Shared host/guest request/response types
│   ├── types/           # Domain data structures
│   ├── storage/         # Storage implementations
│   ├── transcription/   # Transcription support
│   └── llm/             # LLM integration
├── plugins/             # WASM plugin source (5 isolated Go modules)
│   ├── rss/             # RSS XML → episode list
│   ├── downloader/      # Audio download via host http-download capability
│   ├── transcriber/     # Audio → transcript via host http-post capability
│   ├── extractor/       # Transcript → entities via host http-post (Ollama)
│   └── store/           # Persist data via host file-write capability
├── dist/plugins/        # Compiled .wasm files (generated by `make plugins`)
├── go.work              # Workspace: root + 5 plugin modules
└── Makefile             # Build orchestration
```

## Plugin ABI Status

The host kernel (`internal/kernel`) drives wazero directly and implements the
canonical Component Model fat-pointer ABI for `cm.Result[string, string, string]`
by hand: 12-byte layout `[tag u8][pad 3][str_ptr u32][str_len u32]`. All five
host capabilities are registered under the canonical WIT module name
`podpedia:kernel/host-capabilities@0.3.0`:

- `http-fetch(url) -> result<string, string>`
- `http-post(url, body) -> result<string, string>`
- `http-download(url, dest) -> result<_, string>`
- `file-write(path, data) -> result<_, string>`
- `log-msg(msg)`

**Plugin guest side is currently stubbed.** A previous attempt to use
`wit-bindgen-go`'s generated guest bindings collided with Go's wasip1 toolchain,
which rejects `*cm.Result[...]` pointer types in `//go:wasmimport` /
`//go:wasmexport` directives. The chosen path forward is the **SDK Pattern**:
the upstream `github.com/gavmor/wasm-microkernel` repo will publish a `guest/`
package (planned v0.6.0) that hides the raw `uint32`-only wasmimport/wasmexport
shims and exposes a clean API:

```go
import "github.com/gavmor/wasm-microkernel/guest"

func main() { guest.Register(Execute) }
func Execute(reqJSON string) (string, error) { ... }
```

Each plugin's `main.go` is currently a no-op stub with a TODO pointing at this
plan; `logic.go` (real business logic) and the test files are untouched.

- `cavaliergopher/grab` — Audio downloading
- `alitto/pond` — Goroutine worker pools

- `code.cloudfoundry.org/lager/v3` — Structured JSON logging
- `onsi/ginkgo` + `onsi/gomega` — BDD testing

## Usage

```bash
# Build the host binary
go build -o podpedia .

# Build WASM plugins (currently no-op stubs until microkernel v0.6.0 lands)
make plugins

# Run the pipeline
./podpedia run --url <RSS_FEED_URL> --output <OUTPUT_DIR>

# Optional flags
./podpedia run --url <RSS_FEED_URL> \
  --output ./output \
  --plugins ./dist/plugins \
  --ollama http://localhost:11434 \
  --transcribe-url <WHISPER_ENDPOINT>
```

## Development
